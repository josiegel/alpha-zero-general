# Pax Renaissance (2nd Edition) — personal web implementation

A browser version of Pax Renaissance 2E with rules enforcement, for:

- **2 players, hot-seat** on one screen, or
- **1 player vs. a bot**, chosen on the setup screen:
  - **Neural network** (strongest): the trained network in `models/pax-net.json` + `.bin`, run in plain JavaScript (`src/ai/nn.js`). Refresh it from training with `python train/export_web.py runs/ppo2/best.pt`, then check it with `node tools/nn_check.mjs`, which compares the JavaScript network against PyTorch.
  - **Greedy**: tries every option one action ahead and scores the result (see *AI*).
  - **Random**: uniformly random legal moves.
  The bot type is saved with the game, so resumed and loaded games keep it.

## Running

```
node server.mjs          # or: npm start
```

Then open http://localhost:8080. The app needs no dependencies or build step, and any static file server works.

Card, board and map images load from the Steam CDN URLs listed in the Tabletop Simulator save. The card sheets are large (about 18 MB each), so the first load takes a while. After that the browser caches them.

### How to play

- The right-hand panel lists every legal option for the pending decision.
- Legal targets on the board and tableaux glow blue. Clicking a target picks it, or narrows the list when several options share that target.
- Hover over any card, empire square or victory square to see an enlarged preview with its ability text.
- **Undo** steps back one decision. It can go back through earlier actions, and against the bot it rewinds to your last decision.
- The game autosaves to localStorage, and the setup screen offers **Resume**. **Save** downloads a game record (JSON) that **Load game file** can reopen.
- `?demo=N&seed=S` starts a game against the bot and fast-forwards N random decisions. It is useful for testing.

### Engine design (important for a future NN bot)

- The rules are straight-line procedures that call `ctx.choose(player, prompt, options)` whenever a decision is needed.
- Each option has a stable string `id`, a human `label`, and an optional `ref` naming the UI target.
- The controller replays a decision list from a checkpoint taken at the start of each action.
- The whole game is plain JSON and fully reproducible from `(config, seed, answers[])`. That gives undo, save/load and training data for free.
- Every decision is a choice among an explicit list of legal options, so a policy network only needs to score options. Illegal moves are impossible by construction.

## AI

- `RandomAgent.choose(view, request)` returns an option id.
- To plug in a trained model, implement `model.score(obsVec, optionVecs) -> number[]` and wrap it with `PolicyAgent`.
- `encodeObservation(state, player, request)` returns 3,825 floats: the board from `player`'s perspective, the decision context (prompt kind, the main action and Op this decision belongs to, taken from `request.trail`), and a 168 × 17 per-card table (`OBS_LAYOUT` gives section offsets).
- The encoding includes everything a player with perfect memory could know: both hands (cards only enter a hand by purchase from the face-up market) and face-down trade-fair cards that were face up earlier. The engine records those in `state.seen`. Only the deck order and face-down cards never seen face up (the ones dealt at setup, or rarely a card drawn straight into the empty trade-fair slot) stay hidden.
- `encodeOption(state, request, option, player)` returns 244 structured features: verb, target and mentioned empire/city/border, market slot and price, Op type, card owner and static card stats. Slots 0 and 1 hold card embedding indices.
- `node tools/encode_check.mjs 500` (or `npm run encode-check`) checks over self-play games that sizes are fixed, every prompt and option is classified, no hidden information leaks (it re-deals hidden cards and compares encodings), and legal options rarely encode identically.
- Baseline bots (`src/ai/agents.js`): `RandomAgent`, and `GreedyAgent`, which tries every option, finishes the current action twice with random sub-choices (hidden cards re-dealt by `src/ai/determinize.js`, so it can't peek at draws) and scores the result with `src/ai/heuristic.js`. Greedy beats random 100–0.
- `node tools/arena.mjs greedy random 100` plays built-in agents against each other with alternating seats.
- Training and evaluation in Python (PyTorch, NumPy):
  - `tools/envserver.mjs` runs many games at once and talks to Python over a binary stdin/stdout protocol (documented in the file). Seats are either decided by Python or played by a built-in bot.
  - `train/env.py` is the client: `PaxEnv(num_games, seed, opponent, total_games)` returns batches of encoded decisions, and `step(actions)` takes one option index per decision.
  - `train/model.py` holds the policy/value network (`PaxNet`), checkpoint save/load, and policies.
  - `train/eval.py` measures a policy's score against random and greedy: `python train/eval.py --policy random|untrained|ckpt.pt --opponent random greedy --games 200`. Evaluation seeds start at 1,000,000 so they don't overlap training seeds.
  - `train/ppo.py` trains by PPO self-play: `python train/ppo.py --run runs/ppo1` (add `--resume` to continue). About 20% of games are played against frozen snapshots of earlier versions. Useful options:
    - `--greedy-games N` adds N parallel training games against the greedy bot, in a second game server. Self-play games train both seats, so 64 greedy games next to 128 self-play games give about 20% of the data.
    - `--init ckpt.pt` starts from a checkpoint's weights, continuing its iteration numbering.
    - After each evaluation, the best score against greedy so far is kept as `best.pt` (and `best.json`), and best checkpoints join the past-version pool. With `--rollback-after K` (default 2), K evaluations in a row whose 95% range is entirely below the best reload `best.pt`.
    - The current run, `runs/ppo2`, was started with `--init runs/ppo1/ckpt_00060.pt --lr 1e-4 --greedy-games 64 --eval-games 200 --seed 2`.
  - Everything goes into the run folder:
    - `train.log`: one readable line per iteration
    - `log.jsonl`: all metrics, including `eval_random` / `eval_greedy` scores with 95% intervals, every 10 iterations
    - `latest.pt`: model and optimizer state after each iteration, for resuming
    - `ckpt_NNNNN.pt`: a checkpoint at every evaluation
    - `snapshots/`: frozen past versions used as opponents
    - `dashboard.html`: a live view of `log.jsonl`, copied from `train/dashboard.html` when a run starts. Run `npm start` and open `http://localhost:8080/runs/<run>/dashboard.html`; it re-reads the log every 30 seconds. Opened straight from disk, it asks you to pick `log.jsonl` once (Chrome and Edge then keep re-reading it). Charts load d3 from cdnjs, so it needs an internet connection. Its "How games end" section shows how training games ended per iteration (`ends` in the log) and how the bot's evaluation wins and losses ended (`eval_<opponent>_ends`).
  - Self-play throughput with 256 parallel games is about 2,000 decisions/s with random moves and about 1,100/s with the network choosing (one Node process, CPU).
- To generate games quickly, run `node tools/selfplay.mjs 1000`. About 30 random games run per second, which suits self-play reinforcement learning or imitation learning from recorded games.

## Rules notes / interpretations

- All 13 sea and land borders, the 6 trade routes, and the city levy icons for all 4 states of each empire were read from the map card images.
- These card abilities are implemented, keyed by ability name, as described in `state.js`:
  - immunity to silencing, ops on both East and West in one action, Concessions immune to pirates, Behead restrictions, victory actions costing 2 actions
  - patron prestige counting as law, concessions or bishops; vote discounts
  - Ransom, Popular Reprisals, Fortifications (free ops), Republic-counting cards, Condottiere (Venice holds 2), unlimited hand, Buffer State, apostasy immunity
  - Enclosure, Podestà (free trade fair), Counter-Reformation, Cryptography, Patron's Renown, Pragmatic Treachery, Henry VIII, Knights of Rhodes, Cape of Good Hope, Slave Soldiers
- Cryptography follows the card text: when you sell it, you may perform one political Op of an opponent's West card.
- The four promo cards and the Byzantine / "Commonwealth" expansion map cards in the TTS save are not used.
- The bot plays the normal 2-player game. It does not follow the official solitaire rules.
